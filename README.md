\## Опис завдання

Мета роботи - дослідити продуктивність програми накладання імпульсного відгуку на аудіосигнал (основа роботи ревербераторів), виявити вузькі місця за допомогою профайлера `perf` (FlameGraph) та провести апаратну оптимізацію.



\* \*\*Задача:\*\* Згортка (convolution) аудіосигналу з імпульсним відгуком.

\* \*\*Дані:\*\* Обробка масивів чисел із плаваючою комою (float).

\* \*\*Контрольна сума:\*\* Для перевірки цілісності оптимізації виводиться контрольна сума масиву результату `21330316.00` (в обох варіантах значення збіглося абсолютно точно).

\## 2. Побудова та аналіз FlameGraph

Для візуалізації вузьких місць використовувався `perf record` з частотою семплювання та скрипти Брендана Грегга. Для коректного відображення імен функцій код компілювався з прапорцем `-fno-omit-frame-pointer`.



\* \*\*Базова версія (`flame\_unopt.svg`):\*\*

&#x20; Графік має вигляд однієї суцільної смуги. Понад 99.7% усього часу процесор був заблокований у неоптимізованій функції `apply\_ir\_naive`. Решта системних процесів на фоні 3.85 секунд візуально непомітні.

&#x20; 

\* \*\*Оптимізована версія (`flame\_opt.svg`):\*\*

&#x20; Оскільки математичні розрахунки прискорились у майже 38 разів, на графіку стали помітними системні виклики. Зокрема, виділення сторінок пам'яті операційною системою (`page\_fault`) та ініціалізація даних тепер займають вагому частку від загального часу роботи (0.10 сек).

\## 3. Порівняння коду та апаратна оптимізація



\### Зміна алгоритму (Cache-friendly порядок)

У базовій версії внутрішній цикл стрибав по пам'яті великими кроками. В оптимізованій версії ми поміняли цикли місцями. Тепер програма читає дані послідовно (stride-1). Процесор завантажує 64-байтну лінійку кешу L1 і використовує всі дані з неї до того, як вона буде перезаписана. Це зменшило промахи кешу у 34 рази.



\### Векторизація (AVX2 + FMA)

Правильний доступ до пам'яті дозволив компілятору GCC застосувати SIMD-векторизацію (прапорці `-mavx2 -mfma`).



\* \*\*У базовій версії\*\* процесор використовував скалярні інструкції (наприклад, `mulss` та `addss`), обробляючи лише \*\*одне\*\* 32-бітне число float за раз.

\* \*\*В оптимізованій версії\*\* підключаються 256-бітні YMM-регістри та технологія \*\*FMA\*\* (Fused Multiply-Add). Замість окремих операцій додавання і множення, процесор виконує інструкцію `vfmadd231ps`, яка одночасно множить і додає \*\*8 чисел float за один такт процесора\*\*. Саме це зменшило кількість виконаних інструкцій з 26.9 млрд до 490 млн.

\## 4. Заміри енерговитрат

Оскільки прямий доступ до MSR-регістрів процесора (RAPL) у середовищі WSL2 обмежений віртуалізацією, оцінка енергоспоживання проводилась через аналітичний скрипт на базі лічильників `perf stat` та теплопакета процесора.



| Показник | Базова версія | Оптимізована версія | Економія |

| :--- | :--- | :--- | :--- |

| \*\*Енергія системи (Дж)\*\* | 83.47 Дж | 2.23 Дж | \*\*У \~37 разів менше\*\* |

| \*\*Енергія програми (Дж)\*\* | 58.47 Дж | 1.56 Дж | У \~37 разів менше |

| \*\*Середня потужність\*\* | \~21.7 Вт | \~21.7 Вт | Без змін |



\*\*Висновок:\*\* Хоча пікова потужність процесора під навантаженням залишається однаковою, оптимізована програма виконує ту ж саму роботу за мілісекунди. Завдяки цьому процесор миттєво повертається у стан енергозбереження (idle), що дає колосальну економію заряду батареї.
